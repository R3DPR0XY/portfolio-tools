# Commercial Licensing

[Versao em portugues](commercial-licensing.md)

Some projects in this portfolio may be presented only as technical showcases, without releasing source code, builds, or complete configurations.

## When To Keep A Project Closed

Keep a project closed when:

- You want to sell usage licenses.
- You want to charge for installation, support, or customization.
- The code contains valuable business logic.
- The project was made for a specific server.
- Publishing the source would make direct copying easier.

## Recommended Strategy

- Publish README files, screenshots, resources, and case studies.
- Keep the source code in a private repository.
- Distribute only compiled `.jar` files to licensed clients.
- Use obfuscation when it makes sense.
- Include clear terms of use.
- Track changelog and versions.
- Define support scope.

## About Obfuscation

Obfuscation helps make bytecode harder to read and modify, but it does not make a plugin impossible to copy. It should be treated as an extra layer, not the main protection.

Real protection comes from:

- Commercial license.
- Private repository.
- Controlled distribution.
- Contract or terms of use.
- Clear brand/authorship.
- Support and updates as a differentiator.
