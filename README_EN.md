## Project Documentation Standard

Each published item should include its own `README.md` with:

- **Summary:** what the project does in a few lines.
- **Problem solved:** why it exists.
- **Technologies:** languages, frameworks, APIs, or tools used.
- **How to run:** commands and minimum requirements.
- **Examples:** input, output, or usage scenario.
- **Status:** experimental, in development, stable, or legacy.
- **Security:** notes about data, permissions, and environment variables.

## Quality Before Publishing

Before moving any file into this repository:

- Remove tokens, passwords, cookies, API keys, and `.env` files.
- Replace local paths with generic examples.
- Replace personal or private data with fictional data.
- Remove generated, temporary, or heavy files.
- Test the main command for the project.
- Update the project `README.md` with real instructions.

## R3DPR0XY Forge Maps

Forge Maps is a custom format for explaining technical projects with a recognizable R3DPR0XY identity. Instead of generic diagrams, the maps use four structures:

| Map | Use |
| --- | --- |
| Release Rail | Pipelines, builds, packaging, and releases. |
| Runtime Core | Paper plugins and server systems at runtime. |
| Mod Circuit | Fabric mods, entrypoints, mixins, screens, assets, and final JAR output. |
| Showcase Board | Public project snapshots for READMEs, portfolios, and release notes. |

See examples in [docs/forge-maps](docs/forge-maps).
